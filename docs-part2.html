3.1 Real-Time Messaging System

BoardEase implements a full real-time messaging system using Socket.IO as the WebSocket layer and Apache Kafka as the message broker. Messages are delivered instantly to all connected clients in the same chat room.

Chat Rooms Available

adminTenant Messages / AdminDirect channel between tenants and admin
{uuid}Custom GroupsAdmin-created groups with selected members

Kafka Integration Flow

// backend/lib/kafka.js — simplified
async function initKafka(io) {
  await producer.connect();
  await consumer.subscribe({ topic: 'boardease.messages' });
  await consumer.run({
    eachMessage: async ({ message }) => {
      const data = JSON.parse(message.value.toString());
      io.to(data.room).emit('receive_message', data); // broadcast
    }
  });
}

async function publishMessage(data) {
  if (!kafkaReady) return false; // fallback to direct emit
  await producer.send({
    topic: 'boardease.messages',
    messages: [{ value: JSON.stringify(data) }]
  });
  return true;
}

✅ Graceful Fallback: If Kafka is not available (e.g., during local dev without Docker), the system automatically falls back to direct Socket.IO emit — the app never crashes.

Supported Message Features

  • Text messages with timestamps
  • Image sharing (base64 encoded, displayed inline)
  • Image lightbox viewer on click
  • Admin rent reminder broadcast to all tenants
  • Group creation with custom member selection
  • All messages persisted to messages.json

BoardEase uses a hybrid data store: XML files (via xmldom) for payments, messages, logs, and reservations; and JSON files for users, rooms, and groups. All files live inside the project at backend/data/.

📌 Why XML for most data? XML is the primary store because it integrates directly with the XSLT report pipeline — the same payments.xml and users.xml files read by the app are also transformed by XSLT stylesheets for the Admin Reports dashboard. 3.3 Data Access Method — xmldom + JSON File I/O

XML files are read and written using the xmldom library's DOMParser and XMLSerializer. JSON files use Node.js built-in fs with JSON.parse / JSON.stringify. Both live in backend/data/.

XML Read/Write Pattern (payments, messages, logs, reservations)

// backend/models/xmlModel.js
function readXML(file) {
  const raw = fs.readFileSync(path.join(XML_DIR, file), 'utf-8');
  return new DOMParser().parseFromString(raw, 'text/xml');
}

function writeXML(file, doc) {
  fs.writeFileSync(path.join(XML_DIR, file), new XMLSerializer().serializeToString(doc), 'utf-8');
}

JSON Read/Write Pattern (users, rooms, groups)

// backend/models/xmlModel.js
function read(name) {
  return JSON.parse(fs.readFileSync(path.join(JSON_DIR, name + '.json'), 'utf-8'));
}

function write(name, data) {
  fs.writeFileSync(path.join(JSON_DIR, name + '.json'), JSON.stringify(data, null, 2), 'utf-8');
}

XML Update Pattern

function updatePaymentStatus(id, status, reason) {
  const doc = readXML('payments.xml');          // 1. parse XML
  updateNodeById(doc, 'payment', id, {           // 2. find & mutate node
    status, denialReason: reason
  });
  writeXML('payments.xml', doc);               // 3. serialize back to disk
}

3.5 Scripting Integration

BoardEase integrates scripting at multiple levels — from the Docker startup automation to the frontend build pipeline and backend server initialization.

🐳 Docker Compose — Full Stack Orchestration

A single docker compose up --build -d command starts all 6 services (frontend, backend, Kafka, Zookeeper, RabbitMQ, Redis) with health checks ensuring correct startup order.

🦇 start.bat — Windows One-Click Launcher

A Windows batch script checks for Docker installation, runs docker compose up --build -d, and prints all service URLs to the console. Handles errors with clear messages.

🦇 install.bat — Dependency Installer

Runs npm install for both backend and frontend sequentially. Exits with error code if any step fails, preventing partial installations.

⚙️ next.config.js — Build Configuration

Configures Next.js with output: "standalone" for Docker production builds, disables image optimization for XML-served content, and injects the API URL environment variable at build time.

🔐 JWT Middleware — Auth Scripting

The auth.js middleware script intercepts all protected API routes, verifies the JWT token from the Authorization header, and attaches the decoded user object to req.user.

📝 logActivity() — Automated Audit Logging

Every significant action (login, payment, message, notification) automatically calls logActivity(type, detail, ref) which appends a timestamped entry to backend/data/json/logs.json — no manual logging needed.

🌐 Public Landing Page (/)

Animated hero section with live room stats fetched from /api/rooms/stats, about section with animated counters, and a contact form. Fully responsive with hamburger nav.

📝 Tenant Self-Registration (/register)

New tenants can create their own account without admin involvement. Registered accounts default to the tenant role. Fields: full name, username, password, phone, address, emergency contact.

👤 Profile Pages (/admin/profile, /user/profile)

Both admin and tenant users can edit personal details (full name, phone, birthday, address, emergency contact), upload/change their profile avatar, and change their password with current password verification.

📂 Utility Scripts

scripts/seed-room-images.js seeds default room images into the data directory. scripts/sync-rooms-xml.js syncs rooms.json → rooms.xml for XSLT reports.
