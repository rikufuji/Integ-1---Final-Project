Section 1

System Overview

1.1 Purpose of the System

BoardEase is a full-stack web-based boarding house management system designed to digitize and streamline the day-to-day operations of a boarding house. It replaces manual paper-based processes with a centralized digital platform that handles tenant management, room assignments, payment tracking, real-time messaging, and administrative reporting — all accessible from any device including mobile phones.

The system uses XML files as its primary data store for payments, messages, logs, and reservations — parsed and written using the xmldom library. Users, rooms, and groups are stored in JSON files. XSLT transformations are used for admin reports against the same XML files. Real-time communication is powered by Socket.IO with Apache Kafka as the message broker for chat delivery and RabbitMQ for payment event notifications.

💡 Data Store: Payments, messages, logs, and reservations are stored in XML files at backend/data/xml/ using xmldom for parsing and serialization. Users, rooms, and groups use JSON files at backend/data/json/. The same XML files are also used as input for XSLT report generation.

Section 2

System Architecture

2.1 High-Level Architecture

BoardEase follows a client-server architecture with an additional message broker layer. The frontend (Next.js) communicates with the backend (Express) via REST API calls and a persistent WebSocket connection. The backend integrates Kafka and RabbitMQ as asynchronous message brokers, and reads/writes all data to XML files on disk.

2.2 Message Flow — Chat (Kafka)

1
User sends a message

Tenant or admin types a message in the chat UI and submits the form.

2
Socket.IO emits send_message

The frontend emits the event with room ID, sender info, content, and optional image data.

3
Backend publishes to Kafka topic

publishMessage() sends the message to the boardease.messages Kafka topic. If Kafka is unavailable, falls back to direct Socket.IO emit.

4
Kafka consumer broadcasts

The Kafka consumer reads from the topic and calls io.to(room).emit("receive_message") to all connected clients in that room.

5
Message logged to JSON

logActivity() appends an entry to backend/data/json/logs.json with timestamp, type, and content.

2.3 Message Flow — Payments (RabbitMQ)

1
Tenant submits payment

Tenant fills the payment form with amount, method, date, and optional proof image.

2
Backend saves to payments.json

Payment record is written to backend/data/json/payments.json with status pending.

3
Event published to RabbitMQ queue

publishPaymentEvent() sends the payment data to the boardease.payments durable queue.

4
Consumer emits notification

RabbitMQ consumer reads the message and calls io.emit("payment_notification") to notify the admin in real time.
